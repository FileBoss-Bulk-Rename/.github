# FileBoss — bulk rename on a file list you own

FileBoss keeps one named board on the desk: the live file list, the rename in front of you, and a short note the next operator can read. Extra lists wait for their own title.

## Session Card

| Slice | What you do in FileBoss | What remains |
|-------|------------------------|--------------|
| Arrival | Open FileBoss and name today's ops desk | A titled file list |
| Focus | Keep only live names on the FileBoss board | A short folder-tool list |
| Check | Read FileBoss folder tools before a large rename | A confirmed ops desk |
| Handoff | Mark finished renames inside FileBoss | A note for the next operator |

## How FileBoss Sits

FileBoss does not replace a guess in Explorer, the unlabeled rename dump, or a pass on files you do not own. It sits beside them as a named ops desk for one job: which bulk rename is live, which folder tools still match the file list you own, and what the next operator should read.

Extra rename jobs wait for their own title instead of crowding the live list. A FileBoss ops desk stays on owned files only.

A first visit should be one short bulk rename on a file list you own, then the same FileBoss ops desk the next day. That is enough to see if the named file list holds.

## Traffic Light

| Signal | On the FileBoss board | What you do |
|--------|----------------------|-------------|
| Green | Named file list, short live rename | Continue the same bulk rename |
| Amber | Two jobs mixed on one folder-tool pass | Split the list before a large change |
| Red | No title, no note, a guess in Explorer | Stop and name the ops desk first |
| Clear | Handoff written, live renames few | Close FileBoss and leave the ops desk |

## Open Order

1. Open the last FileBoss ops desk, not a new empty file list.
2. Read the folder tools and the last handoff.
3. Finish one visible bulk rename inside FileBoss on files you own.
4. Write what changed, then close with fewer Explorer guesses than you found.
5. If the list feels crowded, drop anything that belongs to a different FileBoss job, and keep the list on owned files only.

## After a Week

A week in FileBoss is not a larger pile of Explorer guesses. It is the same title, a shorter live rename, and a note that still makes sense before the next bulk folder pass. Take finished names off the live set so the next visit starts on the ops desk that is still open.

Other programs stay where they are. FileBoss only keeps the path back: desk name, file list you own, folder tools, handoff.

Leave FileBoss with a quieter ops desk than the one you opened. The next visit should start on that named file list, not on a guess.

## Sign-off

- [ ] The FileBoss workspace name is short enough to scan
- [ ] Only files you own sit on the bulk rename
- [ ] A second operator can read the list handoff
- [ ] The last FileBoss file list still opens after a restart
- [ ] Finished renames are off the live FileBoss set
- [ ] The FileBoss summary still matches the folder tools on the board

## Field Note

FileBoss is easier to trust when the ops desk stays smaller than the Explorer-guess pile it came from. Name the file list, keep the live rename, finish one visible folder-tool pass, and write what changed.

The same loop fits a shop list, a file list handoff, or a shared PC. Open the last FileBoss desk and continue. Do not run folder tools on files you do not own.
